3. Atualização do aplicativo

01

Build

O código TSA é integrado sobre a base Orca e empacotado para a plataforma.

02

Assinatura

O pacote é assinado com a identidade adequada. No build ad hoc, componentes Electron precisam compartilhar a mesma assinatura para o macOS carregar o app.

03

Checksum e release

DMG, ZIP e checksums são publicados no repositório do instalador.

04

Instalação limpa

O instalador remove a cópia de teste anterior, copia o app e confirma a assinatura antes de iniciar.

4. Atualização do DNA

01

Experiência local

Um método usado no projeto gera evidência de resultado, custo, duração e retrabalho.

02

Filtro e sanitização

Segredos, dados de clientes, duplicatas e conteúdo sem evidência são excluídos.

03

Avaliação

O Cadu aprova, rejeita ou pede informação. Aprovação humana e validação técnica são condições diferentes.

04

Release assinado

A nova versão recebe manifesto, hashes, compatibilidade e assinatura. O TSA só aplica uma versão verificada.

05

Fallback local

Se a Central estiver indisponível, o DNA aprovado local continua operando.
